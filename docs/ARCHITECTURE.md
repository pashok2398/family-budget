# Architecture and financial invariants

FastAPI serves the compiled React application and JSON API on one local origin. A single SQLite database uses WAL, foreign keys and explicit write transactions. Alembic owns schema changes. Runtime data defaults to ~/.local/share/family-budget, outside this checkout; Docker uses an external bind directory.

Modules: parsers (explicit, versioned layout contracts), normalization (Decimal and Unicode), ingestion (immutable documents, preview rows, atomic commit), classification (decisions and scoped rules), reconciliation (explicit reversible links), budgeting (plans and fund ledgers), reporting (separate consumption and cash flow), API.

Money is signed integer minor units in storage, Decimal in Python, decimal strings on the wire. Expenses are negative; credits positive. Never sum different currencies. ILS budget reports exclude non-ILS amounts and surface their count. Original currency/amount are retained separately; conversions must be supplied, never guessed.

Accounts own cards. Documents are SHA-256 addressed; batches bind a document to a source and parser version. Persisted import rows preserve all outcomes and explicit ambiguity decisions. A source reference identifies a transaction when supplied; otherwise a semantic fingerprint plus occurrence distinguishes same-day identical purchases. Across different documents without source references, overlapping rows require an explicit duplicate/new decision. Rejected rows remain visible. Commit is atomic, serialized, and rechecks current duplicates.

Transactions retain source provenance, purchase/posting/allocation dates, amount, purpose, scope, category and review state. Splits carry signed portions whose sum must equal the transaction. Classification decisions and audit events append history; updates use optimistic versions. Reconciliation groups store before-state and can be undone. Card settlements and internal transfers are excluded from consumption; bank settlements remain account cash flow. Card purchases never enter bank cash flow. Cash withdrawals are unallocated movements, not inferred household consumption.

Every month-based calculation uses a financial period (`periods.py`): the household-configured start day (1–28, in הגדרות) of the labelled month through the day before that start day in the next month. With start day 10, "2026-10" is 10.10–09.11 inclusive; budgets, reports, funds, commitments and trends all use these bounds. Budget allocations are plans, not cash savings. Fund movements are ledger entries and do not themselves create expenses; linked purchases are counted once. Loan payments are broken into principal/interest; a mortgage or repayment is shown as debt service separately from consumption. Installments represent charged portions, with explicit purchase identifiers and original totals. Remaining commitments are calculated from the latest installment per purchase, never inferred from merchant alone.

Tables include the required accounts, credit_cards, import_batches, source_documents, transactions, transaction_matches, categories, classification_rules, classification_decisions, budgets, budget_allocations, sinking_funds, fund_movements, projects, reimbursements, loans, loan_payments, income_sources, review_items, plus import_rows, transaction_splits, transaction_match_members, recurring_expenses and audit_events. Match membership uses foreign keys; the group also preserves an immutable member-ID snapshot for audit display.

No real bank statements were provided. Hapoalim and Isracard adapters therefore accept only an explicit user-mapped layout or the documented canonical interchange format; native layouts are deliberately unverified. Native PDFs without a verified layout fail closed. PDF table extraction runs in a time/memory-bounded subprocess, with no scripts or external retrieval. Synthetic fixtures test contracts, not bank compatibility.

Implementation references: [SQLite isolation](https://sqlite.org/isolation.html), [SQLAlchemy SQLite transactions](https://docs.sqlalchemy.org/en/20/dialects/sqlite.html), [FastAPI file uploads](https://fastapi.tiangolo.com/tutorial/request-files/).
